# clip-loop — GTA6 日本語 YouTube Shorts 制作ループ

引数（`$ARGUMENTS`）で動作を切り替える。引数が無いときは「探索」だけを行い、制作・投稿はしない。

| 引数 | 内容 | クレジット消費 | 公開投稿 |
|---|---|---|---|
| 探索 | 題材候補を最大3件探して表にする | しない | しない |
| 制作 | 1本分の動画・字幕・タイトル・投稿文を作る | 日次上限内でする | しない |
| 日次 | 探索 → 制作 → 公開 → 記録 を1本分 | 日次上限内でする | する（接続があれば） |
| 分析 | 公開24時間後・7日後の実績を比べ、改善点を1つ決める | しない | しない |

## 保存場所（このスキルを開いたプロジェクト直下）

- `clip-loop/設定.md` — 投稿先チャンネル、日次クレジット上限、予算期間（初回に確認して書く）
- `clip-loop/台帳.md` — 1日1行の記録（下の書式）。二重生成・二重投稿の判定に使う
- `clip-loop/探索/YYYY-MM-DD.md` — その日の候補表
- `clip-loop/制作/YYYY-MM-DD/` — 台本・字幕(.srt)・タイトル・投稿文・素材の出典・完成MP4
- `clip-loop/投稿待ち/YYYY-MM-DD/` — 投稿接続が無い日の完成MP4と投稿文
- `clip-loop/分析/YYYY-MM-DD.md` — 24時間・7日の実績と改善点

日付はすべて日本時間（Asia/Tokyo）で書く。フォルダが無ければ作る。既存のファイルは消さず、追記する。

### 台帳の書式

```
| 日付 | 題材 | 元動画URL | 状態 | 生成ジョブID | 使用クレジット | YouTube動画ID | 24h再生 | 7d再生 | 次回の改善点 |
```

状態は `探索済 → 制作中 → 完成 → 投稿待ち / 公開済` のどれか。

## 探索

1. YouTube を日本語で検索する（例：「GTA6 検証」「GTA6 攻略」「GTA6 小ネタ」「GTA6 解説」）。**直近72時間に公開された動画を優先**し、足りなければ7日以内まで広げる（広げたことを明記する）。
2. 除外するもの：
   - 有名配信者・VTuber・事務所所属のタレント・企業や公式のチャンネル
   - 目安として登録者数がおおむね10万人以上のチャンネル（判断に迷うものは除外する）
   - リーク・違法アップロード・他人の切り抜きの転載
   - 海外チャンネルの自動翻訳タイトル（チャンネル名が外国語で、タイトルだけが日本語のもの）
3. 残った個人の検証・攻略動画から、伸びているもの（経過時間あたりの再生数が多いもの）を **最大3件** 選ぶ。
4. **既存のShortsの実績**と**切り抜き元の長尺動画**は分けて書く。Shortsは「この題材が短尺で伸びる根拠」、長尺は「素材を取る元」として扱い、同じ表で混ぜない。
5. 次の表を `clip-loop/探索/YYYY-MM-DD.md` に保存し、会話にも表示する。

```
| # | 種別(長尺/Shorts) | タイトル | チャンネル | 元動画URL | 再生数 | 公開からの経過時間 | 1時間あたり再生 | 選んだ理由 | 商用利用の根拠 |
```

6. 3件の中からその日の1本を決め、理由を1〜2行で書く。
7. 再生数・経過時間は実際に確認できた値だけを書く。確認できなければ「未確認」と書き、推測しない。
8. 探索ではクレジットを使わず、投稿もしない。

## 制作

1. **素材の可否を先に確認する。** 切り抜きに使えるのは、次のどれかの根拠を確認できた素材だけ。
   - 投稿者が切り抜き・二次利用・収益化を明示的に許可している（概要欄・固定コメント・ガイドラインのURLを控える）
   - Rockstar Games 公式が公開した素材で、同社の利用条件の範囲内
   - 自分で撮った映像、またはライセンスを確認できたフリー素材

   根拠のURLは `制作/YYYY-MM-DD/出典.md` に残す。**根拠が確認できない素材は使わない。**
2. 使える映像が無い日は、**確認済みの事実**（出典URLつき）を、独自の解説・図解・テキストアニメーションで紹介する。元動画の映像・音声は使わない。元動画の紹介はクレジット表記とURLにとどめる。
3. 構成は **20〜40秒・縦 9:16（1080×1920）** にする。
   - 0〜2秒：つかみ（結論や驚きの一言）
   - 本編：検証の手順・結果を3点以内で
   - 最後：まとめと元動画への誘導
4. **Higgsfield MCP** は、視聴者の理解に役立つカットにだけ使う（例：燃料計の比較、マップ上の位置関係、手順の図解、導入カット）。
   - 生成の前に `estimate_image_cost` / `estimate_video_cost` で見積もり、その日の残り予算を超えるなら生成しない。超えそうな日は手作りの図とテキストで代わりにする。
   - Higgsfield の追加購入やプラン変更はしない。
   - 生成した素材には、画面の隅に **「イメージ」** と必ず表示する。
   - 実在のゲーム画面に見せかける生成はしない。ロゴや公式アートの模倣もしない。
   - 生成ジョブIDと使ったクレジットを台帳に書く。
5. 字幕は、全セリフを画面内に表示し、`.srt` も保存する。
6. タイトルは全角32字以内で、「GTA6」と検証内容が分かる言葉を入れる。誇張や事実と違う表現はしない。
7. 投稿文は次の順で書く：要約2行／元動画のクレジット（チャンネル名・URL）／出典／「一部の図解はAIで生成したイメージです」／ハッシュタグ3〜5個（#GTA6 #Shorts を含める）。
8. 完成MP4は ffmpeg などで組み立て、尺・解像度・字幕の表示を確認してから「完成」にする。

## 日次（日本時間で1日1本）

1. **初回の確認**：`clip-loop/設定.md` に投稿先チャンネルと日次クレジット上限が無ければ、ユーザーに一度にまとめて聞き、答えが出るまで制作・投稿をしない（探索だけは進めてよい）。
   - 日次上限が「期間内に残りを使い切る」指定のときは、毎日「その日の残高 ÷ 期限までの残り日数」（切り捨て）で上限を出し直す。ほかのタスクと配分が決まっている場合は、その割合をかける。
2. **重複の確認（必ず最初に）**：今日の日付の行が台帳にあるかを見る。
   - `公開済`：YouTube上にその動画IDがあるかを確かめ、あれば何もせず報告だけして終える。
   - `完成` / `投稿待ち`：作り直さない。投稿接続があれば、YouTubeに同じタイトルの動画がまだ無いことを確かめてから公開する。
   - `制作中`：記録されている生成ジョブIDの結果を取りに行き、新しく生成しない。
   - 行が無い：探索から始める。
3. 探索 → 制作 → 公開 → 記録の順で進める。各段階が終わるたびに台帳の状態を更新する。
4. **公開**：YouTubeに投稿できる接続があれば、設定.md のチャンネルに Shorts として1本公開し、動画IDを台帳に書く。
   - 接続が無い、または失敗した場合は、完成MP4・タイトル・投稿文・字幕を `clip-loop/投稿待ち/YYYY-MM-DD/` に保存し、状態を `投稿待ち` にする。
5. 前日以前の公開分で24時間・7日が過ぎたものがあれば、最後に「分析」を行う。
6. 最後に次の1行で報告する。

```
今日の題材｜選んだ根拠｜制作状況｜使用クレジット｜投稿URLまたは完成ファイルの場所
```

## 分析

1. 台帳の `公開済` のうち、公開から24時間・7日が過ぎたものについて、取得できた実績（再生数、視聴維持率、高評価、コメント、登録者の増減）を記録する。取れない項目は「未取得」と書く。
2. 24時間と7日の実績を比べ、ほかの回とも比べる。
3. **次の動画で変える点を1つだけ**決め、台帳の「次回の改善点」と `clip-loop/分析/YYYY-MM-DD.md` に書く。次の制作では、この改善点を必ず読んで反映する。

## 守ること

- 投稿は日次の中だけで行い、1日1本までにする。探索・制作・分析では投稿しない。
- クレジットは日次上限を超えて使わない。
- 再生数・事実・権利の根拠は、確認できたものだけを書く。
- 実在の配信者の名前や声をまねた生成はしない。
